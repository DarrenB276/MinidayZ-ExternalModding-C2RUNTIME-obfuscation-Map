  CONSTRUCT 2 RUNTIME — MiniDayZ+ 2.3.3 ADDENDUM
  Companion to C2RUNTIME_OBFUSCATION_MAP_COMPLETE_ENG.txt (v1.4–1.9.6)

  PURPOSE: 2.3.3 is minified with the same scheme, but NOT with the same
           letters throughout. This file records what was re-tested against a
           running 2.3.3 build, what still holds, what does NOT, and the
           identifiers the main map does not contain.

  METHOD:  every line below was checked by booting 2.3.3 in a headless browser
           and reading, calling, or diffing the live object, or by reading the
           minified function BODY and matching it against the named
           implementation in an unobfuscated build. Nothing here is carried over
           from the 1.9.6 document on trust.

  ------------------------------------------------------------------------------
  READ THIS FIRST, IT WILL SAVE YOU A DAY
  ------------------------------------------------------------------------------

  Do not verify a mapping with `typeof rt.xx === "function"`. It passes for ANY
  function. Five of the six runtime METHOD names in the main map resolve to real
  functions on 2.3.3 that do something completely different, so the call
  succeeds, returns a plausible value, and corrupts your state quietly.

  PROPERTY names from the main map held up well on 2.3.3 — those can be checked
  by SHAPE (is it an array of types? an object of groups?), which is a real test.
  METHOD names cannot, and must be checked by body.

SECTION A3: WHAT DOES *NOT* HOLD — PLUGIN ACE LETTERS
================================================================================

  Verified counter-examples, read from the bodies and then confirmed by calling
  them on a live sprite:

    1.9.6 map says          2.3.3 actually is
    ---------------------   -------------------------------------------------
    .RB = SetAnimFrame      .RB = SetAnimSpeed
                            body: function(a){this.Oh=pa(a);this.Kg=0<=a;

    .QB = Spawn             .QB = SetAnimFrame    PROVEN
    .PB = SetAnimSpeed      .PB = SetAnim         PROVEN

  The three that matter most, and their bodies:

    OC = function(a){this.Jf=!0;this.mf=this.we.V;
                     1===a&&0!==this.Y&&(this.Rk=0,this.jl||this.Br());
                     this.$f||(this.b.Ef(this),this.$f=!0)}          StartAnim

                       this.$f||(this.b.Ef(this),this.$f=!0);
                       this.jl||this.Mv()}                           SetAnim
    QB = function(a){this.Rk=a;
                     this.$f||(this.b.Ef(this),this.$f=!0);
                     this.jl||this.Br()}                             SetAnimFrame
    Cq = function(a){a&&a!=this.C&&(this.C.ek(this,!0),this.C=a,
                     a.Ok(this,!0),this.b.X=!0)}                     MoveToLayer

  Live test results:

    SetAnimFrame (QB) on t210: frame 2 -> asked 0 -> got 0            PROVEN
    SetAnim      (PB) on t85: "idle_down" -> asked "idle_up" -> got "idle_up"
    MoveToLayer  (Cq) on t590: "test" -> "Layer 0", and present in the new
                               layer's instance list                 PROVEN

  DO NOT derive the rest of the ACE table by zipping the two builds in order.
  It drifts: 1.5.2+ exposes 44 Sprite acts where 2.3.3 exposes 40, and the four
  missing entries shift every name after them. A naive order-alignment produced
  SetAnim=QB and SetAnimFrame=RB, both of which the live test above disproves.
  Function ARITY is a useful checksum for spotting WHERE the drift starts, but it
  cannot realign: too many ACEs take one argument.

SECTION A5: REACHING THE ACE TABLES AT RUNTIME
================================================================================

  On 2.3.3 the plugin objects are NOT reachable from the cr namespace — `cr` is
  not a global and `oc` resolves to an unrelated empty object. Only 408 functions
  are reachable by walking the runtime object, and none of them are ACEs.

  They ARE reachable through any object type:

      var rt   = window.cr_getC2Runtime();
      var type = rt.S.find(function (t) { return t && t.name === "t181"; });
      var plug = type.ja;            // the plugin instance   (NOT type.r)
      plug.k                         // cnds
      plug.n                         // acts
      plug.A                         // exps
      plug.n.QB.call(inst, 3);       // SetAnimFrame

  Two traps:

    * type.plugin is `.ja` in 2.3.3, not `.r` as SECTION 16 gives. `.r` is absent.
    * The ACE functions are installed on a PROTOTYPE
      (`a.prototype.QB = function ...`), so Object.getOwnPropertyNames(plug.n)
      does not list them. Walk the prototype chain, or access them directly.
      The own properties of plug.n are the COMMON world acts only.

SECTION A6: TWO TECHNIQUES THAT DID ALL THE WORK
================================================================================

  1. BODY MATCHING. Take the named implementation from an unobfuscated build,
     reduce it to a shape that survives minification (which property is assigned,
     how many methods are called on `this`, which literals appear), and grep the
     minified file for it. String and number literals survive minification, so
     `d?n.c2=!0:n.uid=b.uid` is a fingerprint you can search for directly.

  2. DEFINITION ORDER, for pairs a body cannot separate. Closure does not reorder
     statements, so functions defined next to each other in the source are still
     next to each other in the output. typeHasNoSaveBehavior sits immediately
     before typeHasPersistBehavior in 1.5.2, and Tt sits immediately before Ut in
     2.3.3, so the pair resolves.

     This works for ADJACENT pairs. It does NOT work across a long run — see the
     Sprite acts drift in SECTION A3.
