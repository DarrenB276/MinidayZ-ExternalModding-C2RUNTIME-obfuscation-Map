SECTION A2: WHAT DOES *NOT* HOLD IN 2.3.3
================================================================================

  1. rt.wy is NOT the objectRefTable.  In 2.3.3 rt.wy holds a string. No array
     on the runtime matches the objectRefTable shape; rt.ya(263) is not callable.
     SECTION 31's index table therefore cannot be used against 2.3.3 as written.

  2. THE PER-PLUGIN ACE LETTERS HAVE SHIFTED.  This is the important one.
     Verified counter-examples, read from the function bodies and then confirmed
     by calling them on a live sprite:

       1.9.6 map says          2.3.3 actually is
       ---------------------   -----------------------------------------------
       .RB = SetAnimFrame      .RB = SetAnimSpeed
                               body: function(a){this.Oh=pa(a);this.Kg=0<=a;
                                     this.$f||(this.b.Ef(this),this.$f=!0)}
                               (Oh = animSpeed, Kg = animForwards, pa = cr.abs)

       .av = SetAnim           .av = SetMirrored / SetScale family
       .QB = Spawn             .QB = SetAnimFrame   (PROVEN)
       .PB = SetAnimSpeed      .PB = SetAnim        (PROVEN)

  3. Do NOT derive the rest of the ACE table by zipping the two builds in order.
     It drifts. 1.5.2+ exposes 44 Sprite acts where 2.3.3 exposes 40, and the
     four missing entries shift every name after them. A naive order-alignment
     produced SetAnim=QB and SetAnimFrame=RB, both of which are wrong and both
     of which the functional test below disproves. Function ARITY is a useful
     checksum for spotting where the drift starts, but it is not sufficient to
     realign: too many ACEs take one argument.

     The reliable method is per-function: read the minified body and match it
     against the named implementation in an unobfuscated build.

  and observing the effect:

    Sprite.acts.SetAnim       →  .PB        PROVEN
    Sprite.acts.SetAnimFrame  →  .QB        PROVEN

    Sprite.acts.StartAnim     →  .OC        (body match; unchanged from 1.9.6)
    Sprite.acts.SetAnimSpeed  →  .RB        (body match)

  Bodies, for anyone re-deriving these:

    OC = function(a){this.Jf=!0;this.mf=this.we.V;
                     1===a&&0!==this.Y&&(this.Rk=0,this.jl||this.Br());
                     this.$f||(this.b.Ef(this),this.$f=!0)}          StartAnim

    PB = function(a,b){this.dj=a;this.Ev=b;
                       this.$f||(this.b.Ef(this),this.$f=!0);

    QB = function(a){this.Rk=a;
                     this.$f||(this.b.Ef(this),this.$f=!0);

    Cq = function(a){a&&a!=this.C&&(this.C.ek(this,!0),this.C=a,
                     a.Ok(this,!0),this.b.X=!0)}                     MoveToLayer

    .Jf  → animPlaying           .Oh  → animSpeed      .Kg → animForwards
    .C.ek() → layer.removeFromInstanceList()
    .C.Ok() → layer.appendToInstanceList()

SECTION A5: REACHING THE ACE TABLES AT RUNTIME
================================================================================

  In 2.3.3 the plugin objects are NOT reachable from the cr namespace — `cr` is
  not a global and `oc` resolves to an unrelated empty object. Only 408 functions
  are reachable by walking the runtime object, and none of them are ACEs.

  They ARE reachable through any object type:

      var rt   = window.cr_getC2Runtime();
      var type = rt.S.find(function (t) { return t && t.name === "t181"; });
      var plug = type.ja;            // the plugin instance   (NOT type.r)
      plug.k                         // cnds
      plug.n                         // acts
      plug.A                         // exps
      plug.n.QB.call(inst, 3);       // SetAnimFrame

  Two traps:

    * type.plugin is `.ja` in 2.3.3, not `.r` as SECTION 16 gives. `.r` is absent.
    * The ACE functions are installed on a PROTOTYPE
      (`a.prototype.QB = function ...`), so Object.getOwnPropertyNames(plug.n)
      does not list them. Walk the prototype chain, or just access them directly.
      Own properties of plug.n are the COMMON world acts only.
