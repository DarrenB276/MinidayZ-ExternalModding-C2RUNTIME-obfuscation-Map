  ПРОЧТИТЕ ЭТО ПЕРВЫМ — СЭКОНОМИТ ВАМ ДЕНЬ РАБОТЫ
  ------------------------------------------------------------------------------

  Не проверяйте сопоставление через `typeof rt.xx === "function"`. Это проходит
  для ЛЮБОЙ функции. Пять из шести имён МЕТОДОВ среды выполнения из основной
  карты на 2.3.3 указывают на реальные функции, которые делают совершенно другое:
  вызов проходит успешно, возвращает правдоподобное значение и тихо портит
  состояние.

  Имена СВОЙСТВ из основной карты на 2.3.3 в основном верны — их можно проверить
  по ФОРМЕ (это массив типов? объект групп?), и это настоящая проверка. Имена
  МЕТОДОВ так проверить нельзя, их нужно сверять по телу функции.

РАЗДЕЛ A5: КАК ДОБРАТЬСЯ ДО ТАБЛИЦ ACE ВО ВРЕМЯ ВЫПОЛНЕНИЯ
================================================================================

  В 2.3.3 объекты плагинов НЕ достижимы через пространство имён cr: `cr` не
  является глобальной переменной, а `oc` указывает на посторонний пустой объект.
  Обходом объекта среды выполнения достижимы лишь 408 функций, и ни одна из них
  не является ACE.

  Но они достижимы через любой тип объекта:

      var rt   = window.cr_getC2Runtime();
      var type = rt.S.find(function (t) { return t && t.name === "t181"; });
      var plug = type.ja;            // экземпляр плагина   (НЕ type.r)
      plug.k                         // cnds
      plug.n                         // acts
      plug.A                         // exps
      plug.n.QB.call(inst, 3);       // SetAnimFrame

  Две ловушки:

    * type.plugin в 2.3.3 — это `.ja`, а не `.r`, как указано в РАЗДЕЛЕ 16.
      `.r` отсутствует.
    * Функции ACE установлены на ПРОТОТИПЕ
      (`a.prototype.QB = function ...`), поэтому
      Object.getOwnPropertyNames(plug.n) их не покажет. Обходите цепочку
      прототипов или обращайтесь к ним напрямую. Собственные свойства plug.n —
      это только ОБЩИЕ world-действия.

РАЗДЕЛ A6: ДВА ПРИЁМА, КОТОРЫЕ СДЕЛАЛИ ВСЮ РАБОТУ
================================================================================

  1. СОПОСТАВЛЕНИЕ ПО ТЕЛУ ФУНКЦИИ. Возьмите именованную реализацию из
     необфусцированной сборки, сведите её к форме, переживающей минификацию
     (какое свойство присваивается, сколько методов вызывается на `this`, какие
     литералы встречаются), и найдите её в минифицированном файле. Строковые и
     числовые литералы минификацию переживают, поэтому `d?n.c2=!0:n.uid=b.uid`
     — это отпечаток, который можно искать напрямую.

  2. ПОРЯДОК ОБЪЯВЛЕНИЯ — для пар, которые не различить по телу. Closure не
     переставляет инструкции, поэтому функции, объявленные рядом в исходнике,
     остаются рядом и в выводе. typeHasNoSaveBehavior стоит непосредственно
     перед typeHasPersistBehavior в 1.5.2, а Tt — непосредственно перед Ut в
     2.3.3, и пара разрешается.

     Это работает для СОСЕДНИХ пар. Это НЕ работает на длинной последовательности
     — см. сдвиг действий Sprite в РАЗДЕЛЕ A3.
